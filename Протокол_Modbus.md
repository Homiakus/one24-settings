## Карта регистров

### Операционные регистры (управление процессом)

| Адрес | Имя (TOML key) | R/W | Назначение | Значения |
|---|---|---|---|---|
| 1 | `ready_status` | R | Готовность контроллера | 0 = готов, 1 = занят |
| 5 | `status_error` | R | Код ошибки | 0 = OK, 1..15 = код ошибки |
| 9 | `cmd_target` | W | Регистр команд | Код команды (см. таблицу команд) |
| 22 | `status_drain` | R | Статус сливной ёмкости | 0 = OK, >0 = переполнение |

### Регистры управления селекторами (сервисный режим)

> **Назначение:** ручная диагностика и настройка. В автоматическом цикле окраски переключение каналов выполняется через команды контроллера (регистр 9, коды 180/200), а не через прямую запись в эти регистры.

| Адрес | Имя (TOML key) | R/W | Назначение | Значения |
|---|---|---|---|---|
| 19 | `selector1_hole` | R/W | Позиция первого селектора | 1..14 (номер отверстия) |
| 20 | `selector2_hole` | R/W | Позиция второго селектора | 1..14 (номер отверстия) |

### Регистры настройки цикла окраски / промывки

| Адрес | Имя (TOML key) | R/W | Назначение | Значения |
|---|---|---|---|---|
| 37 | `current_step` | W | Номер шага цикла | 1..11 (окраска) / `liquid_code` (промывка) |
| 38 | `exposure_time` | R/W | Время экспозиции реагента | секунды, 1..600 |
| 39 | `liquid_fill_volume` | R/W | Количество жидкости для налива | мл × 10 (напр. 50 = 5.0 мл) |
| 40 | `reagent_empty` | R | Сигнал окончания реагента | 0 = реагент есть, 1 = реагент закончился |
| 41 | `reagent_empty_delta` | R/W | Дельта порога окончания реагента | единицы АЦП датчика (0..255) |

### Протокол взаимодействия

1. **Запись команды:** ПО пишет код команды (90–200) в регистр 9 (`cmd_target`)
2. **Контроллер:** выставляет `ready_status` = 1 (занят), выполняет операцию
3. **Завершение:** контроллер выставляет `ready_status` = 0 (готов)
4. **Ошибка:** контроллер записывает код ошибки в регистр 5 (`status_error`)
5. **Опрос:** ПО опрашивает `ready_status` каждые 200 мс, ошибки — после каждой операции

### Особые команды PLC

Из документации контроллера (`[[../09_архив/One24]]`, архив):

- Запись 100 в регистр 9 → обнуление селектора 1
- Запись 110 в регистр 9 → обнуление селектора 2
- Запись 111 в регистр 1 → перезагрузка контроллера

## Коды ошибок (регистр 5)

| Код | Имя | Уровень | Описание |
|---|---|---|---|
| 0x01 | `ERR_SYSTEM` | CRITICAL | Общая ошибка системы |
| 0x04 | `ERR_ROTOR` | SEVERE | Ошибка механизма ротора (не достиг позиции) |
| 0x05 | `ERR_PUMP` | SEVERE | Ошибка насоса (давление / ток) |
| 0x06 | `ERR_MULTIPLEXER` | SEVERE | Ошибка мультиплексора (позиция) |
| 0x07 | `ERR_SENSOR` | HIGH | Ошибка датчика (нет сигнала) |
| 0x08 | `ERR_VALVE` | SEVERE | Ошибка клапана (не открыт/закрыт) |
| 0x09 | `ERR_REAGENT_LOW` | HIGH | Недостаточно реагента |
| 0x0A | `ERR_SAMPLE_PLACEMENT` | HIGH | Ошибка установки пробирок |
| 0x0B | `ERR_GLASS_PLACEMENT` | HIGH | Ошибка установки стекол |
| 0x0C | `ERR_TIMEOUT` | MEDIUM | Превышение таймаута операции |
| 0x0D | `ERR_WASTE_FULL` | SEVERE | Переполнение сливной ёмкости |
| 0x0E | `ERR_ROTOR_SYNC` | SEVERE | Потеря синхронизации роторов |
| 0x0F | `ERR_POWER` | CRITICAL | Ошибка напряжения питания |

### Отображение на UI-экраны ошибок

| Код | Экран UI | Сообщение |
|---|---|---|
| 0x0D (E02) | E02 | Переполнена сливная ёмкость |
| 0x09 (E03) | E03 | Закончился раствор |
| 0x0A (E04) | E04 | Образцы не обнаружены |
| 0x0B (E05) | E05 | Стёкла не обнаружены |
| — (E06) | E06 | Пластина не обнаружена |
| 0x07 (E07) | E07 | Связь потеряна |
| 0x08 (E08) | E08 | Внутренняя ошибка |

> **Примечание:** Коды ошибок 0x01–0x0F описаны в архитектурном документе ISA-88 (`[[apparatus-control-isa88]]`). Текущая реализация кодирует ошибки как `E0X` в UI. При расхождении — реализация ПО (`[[ONE24/11_Software/README]]`) авторитетна.

# Алгоритмы работы с регистрами

## 1. Регистр 37 — Выбор номера шага цикла (`current_step`)

### Назначение

Регистр 37 задаёт номер текущего шага **перед** выполнением команды `stain_cycle` (код 180) или `wash_system` (код 200). Контроллер использует значение этого регистра чтобы определить:
- Какой реагент подавать (выбор канала мультиплексора)
- Какой профиль налива/слива применять

### Допустимые значения

| Режим | Значения | Смысл |
|---|---|---|
| Окраска (`stain_cycle`, код 180) | 1..11 | Номер шага протокола Папаниколау |
| Промывка (`wash_system`, код 200) | `liquid_code` | Код жидкости (напр. 18529, 4744) |

### Алгоритм выполнения шага окраски

```
АЛГОРИТМ: Выполнить один шаг окраски

ВХОД:
    step_number: int          — номер шага (1..11)
    exposure_time: int        — время экспозиции в секундах (рег. 38)
    fill_volume: int          — объём налива (рег. 39)

ПРОЦЕДУРА:
    1. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0:
           ЖДАТЬ 200 мс, ПОВТОРИТЬ шаг 1
           ЕСЛИ время ожидания > 60 с:
               ВЕРНУТЬ ошибку ERR_TIMEOUT

    2. ЗАПИСАТЬ exposure_time в регистр 38
       ── Modbus Write Single Register (06), addr=38, value=exposure_time

    3. ЗАПИСАТЬ fill_volume в регистр 39
       ── Modbus Write Single Register (06), addr=39, value=fill_volume

    4. ЗАПИСАТЬ step_number в регистр 37
       ── Modbus Write Single Register (06), addr=37, value=step_number

    5. ПРОВЕРИТЬ эхо-запись: ПРОЧИТАТЬ регистр 37
       ЕСЛИ значение != step_number:
           ПОВТОРИТЬ шаг 4 (до 3 попыток)
           ЕСЛИ все попытки неудачны:
               ВЕРНУТЬ ошибку ERR_SYSTEM

    6. ЗАПИСАТЬ код команды 180 в регистр 9 (cmd_target)
       ── Modbus Write Single Register (06), addr=9, value=180

    7. ЦИКЛ ОЖИДАНИЯ:
       ready = ПРОЧИТАТЬ ready_status (рег. 1) каждые 200 мс
       ЕСЛИ ready == 0:
           ПЕРЕЙТИ к шагу 8
       ЕСЛИ время ожидания > (exposure_time + 120) с:
           ВЕРНУТЬ ошибку ERR_TIMEOUT

    8. ПРОВЕРИТЬ ошибки:
       error = ПРОЧИТАТЬ status_error (рег. 5)
       ЕСЛИ error != 0:
           ВЕРНУТЬ код ошибки (отображение на UI-экран)
       ИНАЧЕ:
           ВЕРНУТЬ успех

ОШИБКИ:
    ERR_TIMEOUT (0x0C)  — превышение таймаута при ожидании готовности
    ERR_REAGENT_LOW (0x09) — реагент закончился (рег. 40 = 1)
    ERR_SENSOR (0x07)   — датчик не отвечает
```

### Алгоритм выполнения шага промывки

```
АЛГОРИТМ: Выполнить один шаг промывки

ВХОД:
    liquid_code: int         — код жидкости (напр. 18529 = хлорка, 4744 = вода)

ПРОЦЕДУРА:
    1. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0: ЖДАТЬ

    2. ЗАПИСАТЬ liquid_code в регистр 37
       ── Modbus Write Single Register (06), addr=37, value=liquid_code

    3. ПРОВЕРИТЬ эхо (ПРОЧИТАТЬ рег. 37 == liquid_code)

    4. ЗАПИСАТЬ код команды 200 (wash_system) в регистр 9

    5. ЦИКЛ ОЖИДАНИЯ ready_status == 0 (опрос каждые 200 мс)

    6. ПРОВЕРИТЬ status_error (рег. 5)
```

## 2. Регистр 38 — Время экспозиции реагента (`exposure_time`)

### Назначение

Задаёт длительность выдержки реагента на стекле **для текущего шага**. Переопределяет значение по умолчанию из `user_settings.toml`. Позволяет точно настраивать время каждого шага без перекомпиляции конфигурации.

### Параметры

| Параметр | Значение |
|---|---|
| Адрес | 38 |
| Тип | R/W (чтение/запись) |
| Единицы | секунды |
| Диапазон | 1..600 (10 минут) |
| Значение по умолчанию | берётся из `user_settings.toml` → `[parameters.pap_stain.steps[N].target_time_sec]` |
| Modbus-функция записи | 06 Write Single Register |
| Modbus-функция чтения | 03 Read Holding Registers |

### Алгоритм установки времени экспозиции

```
АЛГОРИТМ: Установить время экспозиции для шага

ВХОД:
    exposure_time_sec: int    — желаемое время в секундах (1..600)

ПРОЦЕДУРА:
    1. ВАЛИДАЦИЯ:
       ЕСЛИ exposure_time_sec < 1 ИЛИ exposure_time_sec > 600:
           ВЕРНУТЬ ошибку: "Недопустимое время экспозиции (1..600 с)"

    2. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0:
           ЖДАТЬ освобождения контроллера (опрос каждые 200 мс)

    3. ЗАПИСАТЬ exposure_time_sec в регистр 38
       ── Modbus Write Single Register (06), addr=38, value=exposure_time_sec

    4. ПОДТВЕРДИТЬ ЗАПИСЬ:
       actual = ПРОЧИТАТЬ регистр 38 (03 Read Holding Registers, addr=38, count=1)
       ЕСЛИ actual != exposure_time_sec:
           ПОВТОРИТЬ шаги 3–4 (до 3 попыток)
           ЕСЛИ все попытки неудачны:
               ВЕРНУТЬ ошибку: "Не удалось записать время экспозиции"

    5. ВЕРНУТЬ успех

ПРИМЕЧАНИЯ:
    - Время пишется ДО установки current_step (рег. 37)
    - Фактическое время ожидания ПО = exposure_time + запас 120 с (на налив/слив)
    - При exposure_time = 0 контроллер использует значение по умолчанию
```

### Карта времён по умолчанию (из user_settings.toml)

| Шаг | t (с) | Шаг | t (с) | Шаг | t (с) |
|---|---|---|---|---|---|
| 1 (Спирт 96%) | 10 | 5 (Спирт 87%) | 10 | 9 (Спирт 87%) | 10 |
| 2 (Гематоксилин) | 120 | 6 (OG-6) | 10 | 10 (Спирт 87%) | 10 |
| 3 (Вода) | 10 | 7 (Спирт 96%) | 10 | 11 (Спирт 96%) | 10 |
| 4 (Вода) | 50 | 8 (EA-50) | 120 | — | — |

## 3. Регистр 39 — Количество жидкости для налива (`liquid_fill_volume`)

### Назначение

Задаёт объём реагента, подаваемого на стекло **для текущего шага**. Управляет длительностью работы насоса или количеством импульсов шагового двигателя дозатора в зависимости от реализации контроллера.

### Параметры

| Параметр | Значение |
|---|---|
| Адрес | 39 |
| Тип | R/W (чтение/запись) |
| Единицы | мл × 10 (например, 50 = 5.0 мл) |
| Диапазон | 1..1000 (0.1 мл .. 100.0 мл) |
| Значение по умолчанию | определяется калибровкой системы |
| Modbus-функция записи | 06 Write Single Register |
| Modbus-функция чтения | 03 Read Holding Registers |

### Алгоритм установки объёма налива

```
АЛГОРИТМ: Установить объём налива для шага

ВХОД:
    volume_ml_x10: int        — объём в единицах мл×10 (1..1000)

ПРОЦЕДУРА:
    1. ВАЛИДАЦИЯ:
       ЕСЛИ volume_ml_x10 < 1 ИЛИ volume_ml_x10 > 1000:
           ВЕРНУТЬ ошибку: "Недопустимый объём (0.1..100.0 мл)"

    2. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0:
           ЖДАТЬ освобождения контроллера

    3. ЗАПИСАТЬ volume_ml_x10 в регистр 39
       ── Modbus Write Single Register (06), addr=39, value=volume_ml_x10

    4. ПОДТВЕРДИТЬ ЗАПИСЬ:
       actual = ПРОЧИТАТЬ регистр 39
       ЕСЛИ actual != volume_ml_x10:
           ПОВТОРИТЬ шаги 3–4 (до 3 попыток)

    5. ВЕРНУТЬ успех

ПРИМЕЧАНИЯ:
    - Объём пишется ДО установки current_step (рег. 37)
    - Масштаб мл×10 выбран для точности 0.1 мл
    - Фактический объём зависит от калибровки насоса
    - При volume = 0 контроллер использует калиброванное значение по умолчанию
```

### Рекомендуемые объёмы налива по типам реагентов

| Тип реагента | Рекомендуемый объём (мл) | Значение регистра |
|---|---|---|
| Спирт (фиксация) | 5.0 | 50 |
| Гематоксилин | 3.0 | 30 |
| Вода (промывка) | 8.0 | 80 |
| OG-6 / EA-50 | 4.0 | 40 |
| Спирт (промывка) | 6.0 | 60 |

## 4. Регистр 40 — Сигнал окончания реагента (`reagent_empty`)

### Назначение

**Read-only** регистр. Сигнализирует о том, что текущий реагент закончился (датчик уровня/потока показал отсутствие жидкости). Контроллер устанавливает этот флаг **автоматически** по показаниям датчика, сравнивая с порогом из регистра 41.

### Параметры

| Параметр | Значение |
|---|---|
| Адрес | 40 |
| Тип | R (только чтение) |
| Значения | 0 = реагент в норме, 1 = реагент закончился |
| Modbus-функция чтения | 03 Read Holding Registers |
| Источник данных | Датчик жидкости на входе мультиплексора (вход 0, `input_0_liquid`, рег. 22 сервисной карты) |

### Алгоритм мониторинга реагента

```
АЛГОРИТМ: Мониторинг окончания реагента

КОНТЕКСТ:
    Выполняется фоновая проверка во время каждого шага окраски/промывки.

ПРОЦЕДУРА (сторона контроллера):
    1. ПЕРЕД началом налива:
       raw_sensor = ПРОЧИТАТЬ значение АЦП датчика жидкости
       delta_threshold = ЗНАЧЕНИЕ регистра 41

    2. ЕСЛИ raw_sensor < delta_threshold:
           УСТАНОВИТЬ регистр 40 = 1 (реагент закончился)
           УСТАНОВИТЬ status_error (рег. 5) = 0x09 (ERR_REAGENT_LOW)
           ЗАВЕРШИТЬ текущую операцию
       ИНАЧЕ:
           УСТАНОВИТЬ регистр 40 = 0 (реагент в норме)
           ПРОДОЛЖИТЬ налив

ПРОЦЕДУРА (сторона ПО):
    1. ПОСЛЕ каждого шага окраски:
       empty_flag = ПРОЧИТАТЬ регистр 40
       ЕСЛИ empty_flag == 1:
           ПРОЧИТАТЬ status_error (рег. 5)
           ОСТАНОВИТЬ сценарий
           ОТОБРАЗИТЬ экран E03: "Закончился раствор"
           ПРЕДЛОЖИТЬ пользователю: заменить реагент → продолжить / отменить

    2. ЕСЛИ empty_flag == 0:
           ПРОДОЛЖИТЬ следующий шаг

ПРИМЕЧАНИЯ:
    - Проверка выполняется в начале каждого налива (перед подачей жидкости)
    - При срабатывании регистр 40 держит 1 до сброса контроллера или до следующего успешного налива
    - Сброс регистра 40 происходит автоматически при записи новой команды в рег. 9
```

### Алгоритм реакции на опустошение реагента (сторона UI)

```
АЛГОРИТМ: Обработчик события «Реагент закончился»

ТРИГГЕР:
    status_error (рег. 5) == 0x09 ИЛИ reagent_empty (рег. 40) == 1

ПРОЦЕДУРА:
    1. ПРИОСТАНОВИТЬ текущий сценарий
       - Отменить таймер ожидания ready_status
       - Запомнить текущий шаг (current_step)

    2. ОТОБРАЗИТЬ экран E03:
       - Заголовок: "Закончился раствор"
       - Сообщение: "Реагент шага N (название) закончился."
       - Действия: [Заменить и продолжить] [Отменить цикл]

    3. ЕСЛИ пользователь выбрал [Заменить и продолжить]:
       - СБРОСИТЬ ошибку (если требуется команда сброса)
       - ПОВТОРИТЬ текущий шаг с тем же current_step
       - Вернуться к экрану S15 (окраска)

    4. ЕСЛИ пользователь выбрал [Отменить цикл]:

       - Перейти на S19 (завершение)
       - Записать инцидент в лог аудита
```

## 5. Регистр 41 — Дельта порога окончания реагента (`reagent_empty_delta`)

### Назначение

Задаёт **порог срабатывания** датчика жидкости, ниже которого реагент считается закончившимся. Это значение вычитается из калиброванного «пустого» уровня АЦП для получения границы срабатывания. Позволяет настраивать чувствительность детекции под разные типы реагентов (спирт, вода, гематоксилин имеют разную проводимость/диэлектрическую проницаемость).

### Параметры

| Параметр | Значение |
|---|---|
| Адрес | 41 |
| Тип | R/W (чтение/запись) |
| Единицы | единицы АЦП (0..255) |
| Значение по умолчанию | 10 |
| Modbus-функция записи | 06 Write Single Register |
| Modbus-функция чтения | 03 Read Holding Registers |

### Принцип работы

```
Датчик жидкости (вход 0)
    │
    ├── Нормальный уровень: АЦП ≈ 200..255 (жидкость проводит/отражает)
    │
    ├── Низкий уровень:    АЦП ≈ 10..50  (воздух/пустая трубка)
    │
    └── Порог срабатывания: АЦП < (калиброванное_пусто + delta)
                              где delta = значение регистра 41
```

### Алгоритм настройки дельты

```
АЛГОРИТМ: Настроить порог детекции окончания реагента

ВХОД:
    delta: int                — значение дельты (0..255)

ПРОЦЕДУРА:
    1. ВАЛИДАЦИЯ:
       ЕСЛИ delta < 0 ИЛИ delta > 255:
           ВЕРНУТЬ ошибку: "Недопустимая дельта (0..255)"

    2. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0:
           ЖДАТЬ освобождения

    3. ЗАПИСАТЬ delta в регистр 41
       ── Modbus Write Single Register (06), addr=41, value=delta

    4. ПОДТВЕРДИТЬ ЗАПИСЬ:
       actual = ПРОЧИТАТЬ регистр 41
       ЕСЛИ actual != delta:
           ПОВТОРИТЬ шаги 3–4 (до 3 попыток)

    5. ВЕРНУТЬ успех

РЕКОМЕНДАЦИИ ПО НАСТРОЙКЕ:
    ┌─────────────────────┬──────────┬──────────────────────────────┐
    │ Реагент             │ Дельта   │ Примечание                   │
    ├─────────────────────┼──────────┼──────────────────────────────┤
    │ Спирт (96%, 87%)    │ 5..10    │ Низкая проводимость          │
    │ Гематоксилин        │ 15..25   │ Высокая плотность, тёмный    │
    │ Вода дистилл.       │ 3..8     │ Очень низкая проводимость    │
    │ OG-6 / EA-50        │ 10..20   │ Средняя вязкость             │
    │ Хлорка (промывка)   │ 10..15   │ Хорошая проводимость         │
    └─────────────────────┴──────────┴──────────────────────────────┘

ПРИМЕЧАНИЯ:
    - Слишком маленькая дельта → ложные срабатывания (помехи)
    - Слишком большая дельта  → позднее обнаружение пустого реагента
    - Оптимальное значение подбирается экспериментально на стенде
    - Рекомендуется записывать в лог значение АЦП при каждом наливе
```

### Алгоритм авто-калибровки дельты (опционально)

```
АЛГОРИТМ: Автоматическая калибровка порога детекции

ПРОЦЕДУРА:
    1. ЗАПОЛНИТЬ магистраль реагентом (подача до стабилизации датчика)
    2. ПРОЧИТАТЬ N=10 значений АЦП датчика (вход 0, рег. 22 сервисной карты)
    3. full_value = СРЕДНЕЕ(замеры)
    4. СЛИТЬ реагент, продуть магистраль воздухом
    5. ПРОЧИТАТЬ N=10 значений АЦП пустой магистрали
    6. empty_value = СРЕДНЕЕ(замеры)
    7. delta = (full_value - empty_value) * 0.3   // 30% от размаха
    8. delta = ОКРУГЛИТЬ(delta) + 5                // запас 5 единиц
    9. ЗАПИСАТЬ delta в регистр 41
   10. ВЕРНУТЬ вычисленное delta
```

## 6. Регистр 19 — Позиция первого селектора (`selector1_hole`)

### Назначение

Регистр 19 управляет **первым селектором** (мультиплексором) клапанов. Селектор направляет поток жидкости из выбранного канала (отверстия) в общую магистраль подачи реагента на стекло. Прямая запись номера отверстия в регистр вызывает перемещение селектора в заданную позицию.

### Параметры

| Параметр | Значение |
|---|---|
| Адрес | 19 |
| Тип | R/W (чтение/запись) |
| Диапазон | 1..14 (номера отверстий) |
| Значение по умолчанию | 1 |
| Modbus-функция записи | 06 Write Single Register |
| Modbus-функция чтения | 03 Read Holding Registers |
| Связанный датчик | Вход 9 (`input_9_selector1`, рег. 31 сервисной карты) |
| Связанная команда калибровки | 100 (`calibrate_sel1`) |
| Связанная ошибка | 0x06 (`ERR_MULTIPLEXER`) |

### Алгоритм переключения селектора 1

```
АЛГОРИТМ: Переключить первый селектор на отверстие

ВХОД:
    hole_number: int          — номер отверстия (1..14)

ПРОЦЕДУРА:
    1. ВАЛИДАЦИЯ:
       ЕСЛИ hole_number < 1 ИЛИ hole_number > 14:
           ВЕРНУТЬ ошибку: "Недопустимый номер отверстия (1..14)"

    2. ПРОВЕРИТЬ ready_status (рег. 1)
       ЕСЛИ ready_status != 0:
           ЖДАТЬ освобождения контроллера (опрос каждые 200 мс)
           ЕСЛИ время ожидания > 30 с:
               ВЕРНУТЬ ошибку ERR_TIMEOUT

    3. ЗАПИСАТЬ hole_number в регистр 19
       ── Modbus Write Single Register (06), addr=19, value=hole_number

    4. ПОДТВЕРДИТЬ ЗАПИСЬ (эхо):
       actual = ПРОЧИТАТЬ регистр 19 (03 Read Holding Registers)
       ЕСЛИ actual != hole_number:
           ПОВТОРИТЬ шаги 3–4 (до 3 попыток)
           ЕСЛИ все попытки неудачны:
               ВЕРНУТЬ ошибку: "Не удалось записать позицию селектора 1"

    5. ДОЖДАТЬСЯ ЗАВЕРШЕНИЯ ПЕРЕМЕЩЕНИЯ:
       ready = ПРОЧИТАТЬ ready_status (рег. 1) каждые 200 мс
       ЕСЛИ ready == 0:
           ПЕРЕЙТИ к шагу 6
       ЕСЛИ время ожидания > 15 с:
           ВЕРНУТЬ ошибку ERR_TIMEOUT

    6. ПРОВЕРИТЬ ОШИБКИ:
       error = ПРОЧИТАТЬ status_error (рег. 5)
       ЕСЛИ error == 0x06 (ERR_MULTIPLEXER):
           ВЕРНУТЬ ошибку: "Селектор 1 не достиг позиции"
       ЕСЛИ error != 0:
           ВЕРНУТЬ соответствующий код ошибки

    7. ПРОВЕРИТЬ ДАТЧИК ПОЛОЖЕНИЯ:
       sensor = ПРОЧИТАТЬ сервисный регистр 31 (input_9_selector1)
       ЕСЛИ sensor == 0:
           ЗАПИСАТЬ в лог: "Предупреждение: датчик селектора 1 неактивен"

    8. ВЕРНУТЬ успех (селектор 1 в позиции hole_number)
```
