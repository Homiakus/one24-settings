# ONEPAP.24 Modbus Configurator Desktop

Единое десктопное приложение на **Wails v3 + WebView2** со встроенным автономным Go-бэкендом для настройки технологических шагов, координат селекторов, запуска сервисных программ и диагностики контроллера ONEPAP.24 по Modbus RTU.

## Особенности архитектуры

- **Единый исполняемый файл (.exe)**: Go-бэкенд и все веб-ассеты вшиты прямо в единый бинарник `artifacts/onepap-modbus-configurator.exe`.
- **Без окон консоли**: Нативное окно Windows без всплывающих черных окон терминала (`CREATE_NO_WINDOW`).
- **Легковесность**: Потребление оперативной памяти 15–30 МБ (в 10 раз легче Electron), мгновенный холодный старт (<100 мс).
- **Автономное управление**: Автоматический старт внутреннего сервера, ожидание готовности порта и безопасная остановка при закрытии окна.

## Требования

- Windows 10/11 (с системным WebView2 Runtime);
- PowerShell 7 (`pwsh`);
- Wails v3 CLI и Go toolchain для сборки из исходников;
- USB/UART-порт контроллера, по умолчанию `COM4`, 115200 baud, slave ID 1.

## Быстрый запуск

Из корня репозитория:

```powershell
.\onepap.ps1 doctor
.\onepap.ps1 start
```

Менеджер при необходимости собирает единый EXE, запускает нативное легковесное окно приложения и управляет жизненным циклом бэкенда.

Также доступен запуск в 1 клик через `onepap.cmd`.

Для полностью автоматического выбора порта:

```powershell
.\onepap.ps1 start -Port 0
```

Для запуска только сервера в фоне без GUI-окна:

```powershell
.\onepap.ps1 start -ServerOnly
```

## Единый скрипт управления

| Команда | Назначение |
|---|---|
| `.\onepap.ps1 start` | собрать при необходимости и запустить легковесный браузер (Tao + Wry) |
| `.\onepap.ps1 start -ServerOnly` | запустить только сервер без GUI окна |
| `.\onepap.ps1 stop` | остановить управляемый экземпляр |
| `.\onepap.ps1 restart` | перезапустить сервер |
| `.\onepap.ps1 status` | показать PID, URL, порт и HTTP-состояние |
| `.\onepap.ps1 open` | открыть текущий UI |
| `.\onepap.ps1 build` | собрать единый `artifacts/onepap-modbus-configurator.exe` (Go + Rust) |
| `.\onepap.ps1 test` | запустить тесты |
| `.\onepap.ps1 check` | проверить форматирование, `go vet` и race tests |
| `.\onepap.ps1 doctor` | проверить Go, Rust, HTTP-порт, COM-порты и runtime |
| `.\onepap.ps1 logs` | показать последние журналы запуска |
| `.\onepap.ps1 clean` | удалить сборки, runtime, журналы, профили и кэши |
| `.\onepap.ps1 clean -Deep` | дополнительно удалить кэш Go-модулей |

## Прямой запуск Go

```powershell
cd configurator
go run .
```

Параметры запуска:

```text
-config <path>       TOML-конфигурация
-host <address>      переопределение HTTP host
-port <number>       HTTP-порт; 0 — свободный системный порт
-strict-port         не использовать запасной порт
-runtime-file <path> записать PID, URL и фактический порт в JSON
```

Пример:

```powershell
go run . -port 0
```

## Конфигурация

Основной файл: `configurator/configurator.toml`.

```toml
[server]
host = "127.0.0.1"
port = 8080

[modbus]
port = "COM4"
baudrate = 115200
slave_id = 1
```

При недоступном Modbus-порту веб-интерфейс всё равно запускается. Подключение можно повторить из UI после выбора правильного COM-порта.

```text

├── scripts/                      # расширенные аудит/benchmark/stress сценарии
├── docs/                         # UX-аудит и проектная документация
```

## Проверки

GitHub Actions выполняет:

- `gofmt` для изменённых Go-файлов;
- `go vet ./...`;
- `go test ./... -race -count=1`;
- синтаксическую и smoke-проверку `onepap.ps1` на Windows;
- сборку Windows EXE и публикацию артефакта.

## Безопасность оборудования

Команды движения, калибровки, запуска программ и записи Modbus-регистров необходимо проверять на стенде с доступным аварийным остановом. Не выполняйте сервисные операции при открытой рабочей зоне или неподтверждённых координатах селекторов.
