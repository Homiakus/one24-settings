# Техническое задание: Программа-конфигуратор Modbus ONEPAP.24

## 1. Назначение программы

Программа-конфигуратор (далее — **Modbus Configurator**) — автономное приложение для настройки, диагностики и тестирования цитологического процессора ONEPAP.24 через протокол Modbus RTU.

**Два варианта архитектуры:**
1. **Десктоп** — Wails v2 + Go, оконное приложение Windows (разделы 2.1, 3–8).
2. **Легковесный сервер** — Go + `net/http`, REST API + WebSocket, Web-UI в браузере (раздел 11). Рекомендован для новых разработок.

**Основные задачи:**
- Полная настройка параметров каждого из 11 шагов окраски (время экспозиции, объём налива)
- Чтение всех настроек с контроллера и сохранение изменений обратно
- Раздельный запуск программ (сценариев) окраски, промывки, тестирования
- Диагностика и ручное тестирование исполнительных механизмов

**Целевой пользователь:** сервисный инженер / пусконаладчик, обученный лаборант (режим «только чтение»).

## 2. Технический стек

### 2.1 Основной стек (десктоп)

| Компонент | Технология | Обоснование |
|---|---|---|
| Язык | Go 1.22+ | Единый стек с основным ПО ONEPAP.24 |
| UI-фреймворк | Wails v2 + HTML/vanilla JS | Возможность переиспользовать UI-компоненты из Main-v6 |
| Modbus | goburrow/modbus (RTU) | Совместимость с существующим `rtu_client.go` |
| Конфигурация | TOML (BurntSushi/toml) | Формат, идентичный `user_settings.toml` |
| Сборка | `go build` + Wails packager | Единый `.exe` (WebView2) |
| Совместимость | Windows 10/11 | Целевая платформа заказчика |

### 2.2 Альтернативная архитектура: легковесный сервер

Вместо толстого десктоп-клиента (Wails/WebView2 ≈ 40–80 МБ) предлагается архитектура **легковесного сервера**, который:
- запускается как фоновый процесс (≈ 8–15 МБ RAM),
- обслуживает Web-UI напрямую в браузере (без установки),
- предоставляет REST API для внешней автоматизации,
- доступен с любого устройства в локальной сети (ПК, планшет, телефон).

| Компонент | Технология | Обоснование |
|---|---|---|
| Язык | Go 1.22+ | Единый стек, минимальный runtime |
| HTTP-сервер | `net/http` (stdlib, без фреймворков) | Zero-deps — минимальный бинарник |
| Роутер | `http.ServeMux` (Go 1.22+) | Нативный роутер с параметрами `{id}` |
| WebSocket | `golang.org/x/net/websocket` | Real-time: статус, прогресс цикла, датчики |
| Modbus | goburrow/modbus (RTU) | Общий слой с десктоп-версией |
| Конфигурация | TOML (BurntSushi/toml) | Тот же `user_settings.toml` |
| Статика (UI) | `//go:embed` (Go 1.22 embed) | HTML/JS/CSS вкомпилены в бинарник |
| Сборка | `go build -ldflags="-s -w"` | Один `.exe` ≈ 8–12 МБ |
| Совместимость | Windows 10/11, Linux (RPi) | Кроссплатформенно |

**Альтернативно (если Go нежелателен):**
- Python 3.11 + PyQt6 + `pymodbus` — быстрее прототипирование, но толще runtime
- C# / WPF + `NModbus4` — нативная Windows-интеграция, привычный UI
- Python 3.11 + Flask/FastAPI + `pymodbus` — для серверного варианта, но тяжелее Go-версии

### 3.1 Вкладка «Настройки» — конфигурация шагов окраски

**Назначение:** чтение и запись параметров каждого из 11 шагов протокола.

#### Макет экрана

```
┌──────────────────────────────────────────────────────────┐
│ Настройки окраски                                         │
│                                                          │
│ Протокол: [Папаниколау ▼]                                │
│                                                          │
│ ┌──────┬─────────────────────┬──────────────┬──────────┐ │
│ │ Шаг  │ Реагент              │ Экспозиция   │  Налив   │ │
│ │      │                      │   (сек)      │  (мл×10) │ │
│ ├──────┼─────────────────────┼──────────────┼──────────┤ │
│ │  1   │ Спирт 96% (фикс.)   │  [  10  ]    │ [  50  ] │ │
│ │  2   │ Гематоксилин         │  [ 120  ]    │ [  30  ] │ │
│ │  3   │ Вода дистилл.        │  [  10  ]    │ [  80  ] │ │
│ │  4   │ Вода дистилл.        │  [  50  ]    │ [  80  ] │ │
│ │  5   │ Спирт 87%            │  [  10  ]    │ [  60  ] │ │
│ │  6   │ OG-6                 │  [  10  ]    │ [  40  ] │ │
│ │  7   │ Спирт 96%            │  [  10  ]    │ [  60  ] │ │
│ │  8   │ EA-50                │  [ 120  ]    │ [  40  ] │ │
│ │  9   │ Спирт 87%            │  [  10  ]    │ [  60  ] │ │
│ │ 10   │ Спирт 87%            │  [  10  ]    │ [  60  ] │ │
│ │ 11   │ Спирт 96%            │  [  10  ]    │ [  60  ] │ │
│ └──────┴─────────────────────┴──────────────┴──────────┘ │
│                                                          │
│ Детекция реагента:                                       │
│   Порог дельты АЦП: [  10  ]  (0..255)                  │
│   Текущий статус:   ● Реагент в норме                    │
│                                                          │
│ [Прочитать все настройки]  [Сохранить изменения]          │
│ [Загрузить из файла]       [Сохранить в файл]             │
│                                                          │
│ Последнее чтение: 2026-06-18 14:32:05                    │
│ Последняя запись: 2026-06-18 14:31:00 — OK               │
└──────────────────────────────────────────────────────────┘
```

#### Поведение кнопок

| Кнопка | Действие | Modbus-операции |
|---|---|---|
| **Прочитать все настройки** | Последовательно читает рег. 38, 39, 41 для всех 11 шагов + читает рег. 40 | 11 × (Write 37, Read 38, Read 39, Read 40) + Read 41 |
| **Сохранить изменения** | Записывает все изменённые пользователем значения в контроллер | 11 × (Write 37, Write 38, Write 39) + Write 41 |
| **Загрузить из файла** | Открывает `user_settings.toml`, парсит секцию `[parameters.pap_stain]`, заполняет таблицу | — |
| **Сохранить в файл** | Экспортирует текущие значения таблицы в `user_settings.toml` | — |

#### Алгоритм «Прочитать все настройки»

```
АЛГОРИТМ: Прочитать все настройки окраски с контроллера

ПРОЦЕДУРА:
    1. ПРОВЕРИТЬ подключение:
       ready = ReadRegister(1)
       ЕСЛИ ошибка: ПОКАЗАТЬ "Нет связи с контроллером", ВЫЙТИ

    2. ДЛЯ step ОТ 1 ДО 11:
       2.1. ЖДАТЬ ready_status == 0
       2.2. WriteRegister(37, step)              // выбрать шаг
       2.3. Проверить эхо: ReadRegister(37) == step
       2.4. exposure[step] = ReadRegister(38)    // прочитать время
       2.5. volume[step]   = ReadRegister(39)    // прочитать объём

    3. delta = ReadRegister(41)                  // порог детекции

    4. reagent = ReadRegister(40)                // статус реагента

    5. ОТОБРАЗИТЬ все значения в таблице
    6. ЗАПИСАТЬ в лог: "Прочитано: step=1..11, delta=N, reagent=N"

ОШИБКИ:
    - Таймаут на любом шаге → остановка, подсветка проблемной строки красным
    - Эхо не совпало → повтор до 3 раз, затем ошибка
```

#### Алгоритм «Сохранить изменения»

```
АЛГОРИТМ: Сохранить изменённые настройки в контроллер

ПРОЦЕДУРА:
    1. ПОСТРОИТЬ список изменённых шагов (грязные поля в таблице)

    2. ЕСЛИ список пуст:
       ПОКАЗАТЬ "Нет изменений для сохранения", ВЫЙТИ

    3. ДЛЯ каждого изменённого шага step:
       3.1. ЖДАТЬ ready_status == 0
       3.2. WriteRegister(37, step)              // выбрать шаг
       3.3. ЕСЛИ время изменено:
            WriteRegister(38, exposure[step])
            Проверить эхо ReadRegister(38)
       3.4. ЕСЛИ объём изменён:
            WriteRegister(39, volume[step])
            Проверить эхо ReadRegister(39)

    4. ЕСЛИ дельта изменена:
        WriteRegister(41, delta)
        Проверить эхо ReadRegister(41)

    5. ПОКАЗАТЬ результат: "Сохранено N параметров"
    6. СБРОСИТЬ флаги «грязных» полей
    7. ЗАПИСАТЬ в лог: "Записано: шаги=[...], delta=N"

ОШИБКИ:
    - Контроллер занят (ready_status=1 более 60 с) → таймаут
    - Эхо не совпало → пометить строку как "Ошибка записи"
    - Частичная запись → показать, какие шаги записаны, какие нет
```

#### Кнопки запуска и Modbus-команды

| Кнопка | Код команды (рег. 9) | Предварительная настройка |
|---|---|---|
| Проверка системы | 90 → (ждём) → 100 → (ждём) → 120 → (ждём) → 130 | — |
| Загрузка образцов | 140 | — |
| Осаждение | 160 | — |
| Цикл окраски | 180 (для каждого шага 1..11) | Рег. 37 = step, Рег. 38 = t, Рег. 39 = v |
| Промывка | 200 (для каждого кода жидкости) | Рег. 37 = liquid_code |
| Полный цикл | 90→100→120→130→140→160→(11×180)→(4×200) | Как выше |
| **СТОП ВСЁ** | 111 в рег. 1 (сброс контроллера) | Аварийный |

#### Алгоритм запуска полного цикла окраски

```
АЛГОРИТМ: Запустить полный цикл окраски (11 шагов)

ВХОД:
    steps[1..11]: {exposure_time, fill_volume}  — из вкладки «Настройки»

ПРОЦЕДУРА:
    ДЛЯ i ОТ 1 ДО 11:
        ЕСЛИ нажата [⏸ Пауза]:
            ЖДАТЬ, пока не нажата [▶ Продолжить] или [■ Стоп]
        ЕСЛИ нажат [■ Стоп]:
            ПРЕРВАТЬ цикл, ВЫПОЛНИТЬ drain_intermediate (код 130)
            ВЕРНУТЬ "Цикл прерван пользователем"

        // Шаг 1: установить параметры
        ЖДАТЬ ready_status (рег. 1) == 0
        WriteRegister(38, steps[i].exposure_time)   // время
        WriteRegister(39, steps[i].fill_volume)      // объём
        WriteRegister(37, i)                         // номер шага

        // Шаг 2: запустить окраску
        WriteRegister(9, 180)                        // stain_cycle

        // Шаг 3: ждать завершения
        timeout = steps[i].exposure_time + 120       // запас 120 с на налив/слив
        ЦИКЛ:
            ready = ReadRegister(1)
            ЕСЛИ ready == 0: ПРЕРВАТЬ цикл ожидания
            ЕСЛИ прошло > timeout: ОШИБКА таймаут
            ЕСЛИ нажат [■ Стоп]: ПРЕРВАТЬ
            ЖДАТЬ 200 мс

        // Шаг 4: проверить ошибки
        error = ReadRegister(5)
        ЕСЛИ error == 0x09 (ERR_REAGENT_LOW):
            ПОКАЗАТЬ диалог: "Закончился реагент на шаге i"
            ЖДАТЬ пользователя: [Заменить и продолжить] / [Отмена]
            ЕСЛИ Отмена: ПРЕРВАТЬ
            ЕСЛИ Продолжить: ПОВТОРИТЬ шаг i (i = i - 1)
        ЕСЛИ error != 0:
            ПОКАЗАТЬ ошибку, ПРЕРВАТЬ

        // Шаг 5: обновить прогресс
        ОБНОВИТЬ progress_bar: i/11
        ОБНОВИТЬ статус: "шаг i завершён"

    ВЕРНУТЬ "Цикл окраски завершён успешно"
```

```
│ │  │ [Спирт 96% (7)]  [EA-50 (8)]                 │  │   │

│ │  Текущая позиция: отверстие 1 (Спирт 96%)         │   │
│ │  Датчик: ● активно                                 │   │
│ │                                                    │   │
│ │  [Калибровка сел. 1]  [Калибровка сел. 2]          │   │
│ └────────────────────────────────────────────────────┘   │
│                                                          │
#### Поведение переключателя селекторов

1. **Выбор селектора:** радиокнопки `[● Селектор 1] [○ Селектор 2]` переключают активный селектор. При переключении:
   - Обновляется список доступных отверстий (оба селектора имеют одинаковый набор 1..14)
   - Подсвечивается текущая позиция выбранного селектора (активная кнопка жидкости)
   - Отображается состояние датчика выбранного селектора (вход 9 для сел. 1, вход 10 для сел. 2)

2. **Кнопки жидкостей:** каждая кнопка отображает название жидкости и номер отверстия в скобках, например `[Спирт 96% (1)]`. При нажатии:
   - Считывается номер отверстия из скобок (аргумент кнопки)
   - Определяется активный селектор (1 → регистр 19, 2 → регистр 20)
   - Отправляется Modbus-команда: Write Single Register (06) в регистр 19 или 20 со значением hole_number
   - Выполняется эхо-чтение для подтверждения
   - Обновляется индикатор «Текущая позиция»
   - Обновляется состояние датчика

3. **Индикация:**
   - Активная кнопка (текущая позиция) подсвечивается зелёным
   - Во время перемещения кнопка мигает жёлтым
   - При ошибке (ERR_MULTIPLEXER) кнопка подсвечивается красным
   - Датчик: ● зелёный = активен, ○ серый = неактивен

#### Алгоритм переключения селектора через UI

```
АЛГОРИТМ: Обработчик нажатия кнопки жидкости

ВХОД:
    hole_number: int          — номер отверстия из кнопки (1..14)
    active_selector: int      — выбранный селектор (1 или 2)

ПРОЦЕДУРА:
    1. ОПРЕДЕЛИТЬ целевой регистр:
       reg = 19 ЕСЛИ active_selector == 1, ИНАЧЕ 20

    2. ПРОВЕРИТЬ ready_status (рег. 1):
       ЕСЛИ ready_status != 0:
           ПОКАЗАТЬ предупреждение: "Контроллер занят, ожидайте..."
           ЖДАТЬ до 30 с
           ЕСЛИ таймаут: ПОКАЗАТЬ ошибку, ВЫЙТИ

    3. ОТПРАВИТЬ команду:
       WriteRegister(reg, hole_number)
       ── Modbus Write Single Register (06), addr=reg, value=hole_number

    4. ПОДТВЕРДИТЬ (эхо):
       actual = ReadRegister(reg)
       ЕСЛИ actual != hole_number:
           ПОВТОРИТЬ шаги 3–4 (до 3 попыток)
           ЕСЛИ все попытки неудачны:
               ПОКАЗАТЬ "Ошибка записи в селектор"
               ВЫЙТИ

    5. ДОЖДАТЬСЯ ready_status == 0 (опрос каждые 200 мс, таймаут 15 с)

    6. ПРОВЕРИТЬ status_error (рег. 5):
       ЕСЛИ error == 0x06 (ERR_MULTIPLEXER):
           ПОКАЗАТЬ "Селектор не достиг позиции"
       ЕСЛИ error != 0:
           ПОКАЗАТЬ соответствующий код ошибки

    7. ОБНОВИТЬ UI:
       - Подсветить кнопку hole_number зелёным
       - Снять подсветку с предыдущей кнопки
       - Обновить "Текущая позиция: отверстие N (название)"
       - Обновить индикатор датчика

    8. ЗАПИСАТЬ в лог: "Селектор {active_selector} → отверстие {hole_number}"
```

> **Примечание:** Это сервисный режим — используется только при ручной диагностике и настройке. В автоматическом цикле окраски переключение каналов выполняется через команды контроллера (регистр 9, коды 180/200), а не через прямую запись в регистры 19/20.
```

### 5.2 Универсальный шаблон записи с проверкой

```go
func SafeWriteRegister(addr uint16, value uint16) error {
    // 1. Проверить готовность
    if err := WaitReady(60 * time.Second); err != nil {
        return fmt.Errorf("контроллер не готов: %w", err)
    }
    
    // 2. Записать
    if err := WriteRegister(addr, value); err != nil {
        return fmt.Errorf("ошибка записи регистра %d: %w", addr, err)
    }
    
    // 3. Подтвердить эхо
    actual, err := ReadRegister(addr)
    if err != nil {
        return fmt.Errorf("ошибка эхо-чтения регистра %d: %w", addr, err)
    }
    if actual != value {
        return fmt.Errorf("эхо не совпало: записано %d, прочитано %d", value, actual)
    }
    
    return nil
}

func WaitReady(timeout time.Duration) error {
    deadline := time.Now().Add(timeout)
    for time.Now().Before(deadline) {
        ready, err := ReadRegister(1)
        if err != nil {
            return err
        }
        if ready == 0 {
            return nil
        }
        time.Sleep(200 * time.Millisecond)
    }
    return fmt.Errorf("таймаут ожидания ready_status")
}
```

### 5.3 Обработка ошибок Modbus

| Ошибка Modbus | Действие |
|---|---|
| Таймаут ответа | Повтор до 3 раз с задержкой 500 мс |
| Exception Code 02 (Illegal Data Address) | Показать: «Регистр не существует» |
| Exception Code 03 (Illegal Data Value) | Показать: «Недопустимое значение» |
| Ошибка порта (COM недоступен) | Показать: «Порт занят или не существует» |
| 3 последовательных таймаута | Показать экран E07: «Связь потеряна» |

## 6. Требования к UI

### 6.1 Общие требования
- **Язык интерфейса:** русский
- **Шрифт:** моноширинный для числовых полей
- **Валидация:** на клиенте до отправки Modbus-команды
- **Блокировка:** кнопки неактивны, если `ready_status=1` или нет подключения
- **Индикация:** цветовая — красный (ошибка/занят), зелёный (OK/готов), жёлтый (ожидание)

### 6.2 Валидация полей ввода

| Поле | Мин | Макс | Сообщение при ошибке |
|---|---|---|---|
| Экспозиция (рег. 38) | 1 | 600 | «Время должно быть 1..600 секунд» |
| Налив (рег. 39) | 1 | 1000 | «Объём должен быть 0.1..100.0 мл» |
| Дельта (рег. 41) | 0 | 255 | «Дельта должна быть 0..255» |

### 6.3 Поведение при запуске
1. Попытаться открыть COM4 с сохранёнными параметрами
2. Если не удалось — показать диалог выбора порта
3. Прочитать `ready_status` (рег. 1) — подтверждение связи
4. Прочитать `status_error` (рег. 5) — если ошибка, подсветить
5. Активировать вкладку «Настройки»

```
│                    ┌───────┴────────┐                            │
│                    │  Контроллер    │                            │
│                    │  ESP32 /       │                            │
│                    │  Medtechnica   │                            │
│                    └────────────────┘                            │
└─────────────────────────────────────────────────────────────────┘
```

**Принцип работы:**
1. Сервер запускается на Windows-ПК (или Raspberry Pi), подключённом к контроллеру через USB/UART.
2. Открывает HTTP-порт `:8080`.
3. Раздаёт вкомпиленный Web-UI (HTML/JS/CSS) как статику.
4. Предоставляет REST API для всех операций с контроллером.
5. Через WebSocket пушит real-time события: статус, прогресс, ошибки, показания датчиков.
6. Modbus-клиент внутри сервера один — конкурентный доступ сериализуется мьютексом.

### 11.3 REST API

**Базовый URL:** `http://<host>:8080/api/v1`

**Формат ответа (всегда):**

```json
{
  "ok": true,
  "data": { ... },
  "error": ""
}
```

При ошибке `"ok": false`, `"error"` содержит описание.

#### 11.3.1 Подключение и статус

| Метод | Путь | Описание | Параметры |
|---|---|---|---|
| `GET` | `/status` | Статус подключения, `ready_status`, `status_error` | — |
| `POST` | `/connect` | Открыть COM-порт | `{"port":"COM4","baudrate":115200,"slave_id":1}` |
| `POST` | `/disconnect` | Закрыть COM-порт | — |
| `GET` | `/ports` | Список доступных COM-портов | — |

**`GET /api/v1/status`** → пример ответа:

```json
{
  "ok": true,
  "data": {
    "connected": true,
    "port": "COM4",
    "baudrate": 115200,
    "slave_id": 1,
    "ready_status": 0,
    "status_error": 0,
    "error_name": "",
    "uptime": "02:34:12",
    "errors_count": 0
  }
}
```

#### 11.3.2 Настройки шагов окраски

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/settings/steps` | Прочитать ВСЕ 11 шагов (time + volume) |
| `GET` | `/settings/steps/{id}` | Прочитать один шаг (id=1..11) |
| `PUT` | `/settings/steps/{id}` | Записать один шаг |
| `POST` | `/settings/read-all` | Полное чтение с контроллера (алгоритм п. 3.1) |
| `POST` | `/settings/write-all` | Полная запись на контроллер |
| `GET` | `/settings/detection` | Прочитать дельту и статус реагента |
| `PUT` | `/settings/detection` | Записать дельту `{"delta":10}` |
| `GET` | `/settings/file` | Прочитать настройки из TOML-файла (без Modbus) |
| `POST` | `/settings/file` | Записать настройки в TOML-файл (без Modbus) |

**`GET /api/v1/settings/steps`** → пример ответа:

```json
{
  "ok": true,
  "data": {
    "protocol": "pap_stain",
    "steps": [
      {"id":1, "name":"Спирт 96% (фикс.)", "exposure_time":10, "fill_volume":50, "dirty":false},
      {"id":2, "name":"Гематоксилин",         "exposure_time":120,"fill_volume":30, "dirty":true},
      ...
    ],
    "detection": {
      "reagent_empty": false,
      "reagent_empty_delta": 10,
      "dirty": false
    },
    "read_at": "2026-06-18T14:32:05+03:00",
    "written_at": null
  }
}
```

**`PUT /api/v1/settings/steps/3`** → тело запроса:

```json
{
  "exposure_time": 15,
  "fill_volume": 80
}
```

Сервер только обновляет in-memory состояние, помечает `dirty: true`. Фактическая запись на контроллер — по явному `POST /settings/write-all`.

#### 11.3.3 Программы (запуск сценариев)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/programs/system-check` | Проверка системы |
| `POST` | `/programs/load` | Загрузка образцов |
| `POST` | `/programs/sedimentation` | Осаждение |
| `POST` | `/programs/stain/start` | Запустить цикл окраски (11 шагов) |
| `POST` | `/programs/stain/pause` | Пауза |
| `POST` | `/programs/stain/resume` | Продолжить |
| `POST` | `/programs/stain/stop` | Остановить с drain |
| `POST` | `/programs/wash/start` | Запустить промывку |
| `POST` | `/programs/full/start` | Полный цикл |
| `POST` | `/programs/emergency-stop` | Аварийный стоп (код 111) |

**`POST /api/v1/programs/stain/start`** → тело (опционально):

```json
{
  "steps": [1, 11]
}
```

Если не указано — все 11 шагов. Если `[2, 5]` — только шаги 2..5.

Ответ (немедленный):

```json
{
  "ok": true,
  "data": {
    "status": "running",
    "program": "stain",
    "current_step": 1,
    "total_steps": 11,
    "message": "Цикл окраски запущен"
  }
}
```

Далее прогресс идёт через WebSocket (см. 11.4).

### 11.4 WebSocket API

**Endpoint:** `ws://<host>:8080/ws/events`

После подключения клиент получает поток JSON-событий. Подписка на категории указывается параметром `?topics=status,progress,sensors`.

#### Формат события

```json
{
  "type": "progress",
  "timestamp": "2026-06-18T14:32:05.123+03:00",
  "data": {
    "program": "stain",
    "current_step": 5,
    "total_steps": 11,
    "step_name": "Спирт 87%",
    "phase": "exposure",
    "elapsed_sec": 8,
    "total_sec": 10,
    "message": "Экспозиция 8/10 с"
  }
}
```

#### Типы событий (`type`)

| Тип | Когда | `data` (ключи) |
|---|---|---|
| `status` | Изменение `ready_status` или `status_error` | `ready_status`, `status_error`, `error_name`, `error_code` |
| `progress` | Шаг цикла — смена, прогресс экспозиции | `program`, `current_step`, `total_steps`, `step_name`, `phase`, `elapsed_sec`, `total_sec` |
| `sensors` | Периодический опрос датчиков (0.5–1 с) | `inputs` (массив 13 bool), `mcu_temp`, `ntc_temp`, `hx711_weight` |
| `reagent` | Изменение статуса реагента | `reagent_empty`, `delta` |
| `error` | Любая ошибка контроллера или связи | `code`, `message`, `context` |
| `log` | Новая запись в журнале | `level`, `message`, `timestamp` |
| `disconnect` | Обрыв связи | `reason` |
| `connect` | Восстановление связи | `port`, `baudrate` |

#### Пример: клиент на vanilla JS

```javascript
const ws = new WebSocket('ws://localhost:8080/ws/events?topics=status,progress,sensors');

ws.onmessage = (e) => {
  const event = JSON.parse(e.data);
  switch (event.type) {
    case 'status':
      updateStatusBar(event.data);
      break;
    case 'progress':
      updateProgressBar(event.data);
      break;
    case 'sensors':
      updateSensorPanel(event.data);
      break;
    case 'error':
      showErrorDialog(event.data);
      break;
  }
};
```

### 11.5 Конфигурация сервера (`modbus-server.toml`)

```toml
[server]
  port = 8080
  host = "0.0.0.0"          # 0.0.0.0 = доступ по сети, 127.0.0.1 = только локально
  cors_enabled = true        # разрешить кросс-доменные запросы
  log_level = "info"         # debug, info, warn, error

[modbus]
  port = "COM4"
  baudrate = 115200
  data_bits = 8
  stop_bits = 1
  parity = "N"
  slave_id = 1
  timeout_ms = 500           # таймаут на один запрос
  retries = 3                # повторов при таймауте
  retry_delay_ms = 500

[features]
  auto_reconnect = true      # пытаться переподключаться при обрыве
  sensor_poll_interval_ms = 500   # интервал опроса датчиков
  progress_emit_interval_ms = 200 # интервал отправки progress в WS

[files]
  user_settings = "../config/user_settings.toml"  # путь к файлу настроек
  log_file = "./modbus-server.log"                # путь к файлу лога
```

### 11.6 Запуск и жизненный цикл

#### Запуск

```bash
# Windows (консоль)
modbus-server.exe --config modbus-server.toml

# Windows (фоновый сервис — через sc.exe или nssm)
nssm install ModbusConfigurator "C:\...\modbus-server.exe" "--config C:\...\modbus-server.toml"
nssm start ModbusConfigurator

# Linux / Raspberry Pi (systemd)
[Unit]
Description=Modbus Configurator ONEPAP.24
After=network.target

[Service]
Type=simple
ExecStart=/opt/one24/modbus-server --config /etc/one24/modbus-server.toml
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

#### Жизненный цикл

```
1. ЗАГРУЗКА
   ├── Парсинг флагов командной строки (--config, --port, --debug)
   ├── Чтение modbus-server.toml
   ├── Инициализация Modbus-клиента (без открытия порта)
   ├── Регистрация API-роутов
   └── Запуск HTTP-сервера

2. РАБОТА
   ├── При первом GET/POST, требующем Modbus:
   │   └── Автооткрытие COM-порта (если ещё не открыт)
   ├── Все Modbus-вызовы под мьютексом (один клиент)
   ├── WebSocket-хаб рассылает события подписчикам
   └── При обрыве связи: auto_reconnect

3. ОСТАНОВКА
   ├── SIGINT / Ctrl+C → grace period 5 с → закрытие
   ├── Закрытие COM-порта
   ├── Завершение активных циклов (с drain по возможности)
   └── Запись лога на диск
```

#### Фоновый режим (systray)

Опционально: иконка в системном трее Windows с меню:
- **Открыть в браузере** → `http://localhost:8080`
- **Статус** — зелёный/красный индикатор
- **Выход** — остановка сервера

Реализуется через библиотеку `getlantern/systray` (~200 строк кода).

### 11.7 Безопасность

Поскольку прибор работает в **изолированной лабораторной сети** (или прямое подключение ПК–контроллер), требования минимальны:

| Уровень | Мера |
|---|---|
| Сеть | `host: "127.0.0.1"` по умолчанию — только локальный доступ |
| CORS | Включён для SPA с других портов; опционально отключается |
| Аутентификация | Не требуется (доверенная среда); опционально — API-ключ в заголовке `X-API-Key` |
| Логирование | Все Modbus-операции и HTTP-запросы пишутся в лог |
| Защита от гонок | Все Modbus-вызовы под `sync.Mutex` |

**Опционально (для сетевого доступа):**

```toml
[security]
  api_key = "changeme"           # простой статический ключ
  rate_limit_per_sec = 20        # лимит запросов
```

Проверка ключа — middleware:

```go
func (s *Server) authMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if s.cfg.APIKey != "" {
            key := r.Header.Get("X-API-Key")
            if key != s.cfg.APIKey {
                api.Error(w, http.StatusUnauthorized, "неверный API-ключ")
                return
            }
        }
        next.ServeHTTP(w, r)
    })
}
```

### 11.9 Приёмочные критерии (сервер)

| № | Тест | Критерий |
|---|---|---|
| С1 | Запуск сервера | Порт :8080 открыт, `GET /api/v1/status` возвращает JSON |
| С2 | Автоподключение | При первом Modbus-запросе COM-порт открывается автоматически |
| С3 | Чтение 11 шагов через API | `POST /api/v1/settings/read-all` → 11 записей в ответе |
| С4 | Запись параметра | `PUT /api/v1/settings/steps/1` → эхо подтверждено |
| С5 | Запуск цикла окраски | `POST /api/v1/programs/stain/start` → цикл выполняется, progress идёт через WS |
| С6 | WebSocket-события | Подписчик получает `progress`, `sensors`, `status` без задержки > 500 мс |
| С7 | Аварийный стоп | `POST /api/v1/programs/emergency-stop` → контроллер сброшен |
| С8 | Обрыв связи | WebSocket-событие `disconnect`, сервер пытается переподключиться |
| С9 | Статический UI | `GET /` возвращает HTML-страницу, вкладки работают |
| С10 | Фоновый режим | Иконка в трее, меню, закрытие через неё |
| С11 | Кроссплатформенность | Сборка под Windows и Linux без изменения кода |
| С12 | Конкурентные запросы | Два одновременных API-вызова не вызывают гонку Modbus |
